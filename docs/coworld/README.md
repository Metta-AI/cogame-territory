# Packaging Territory as a Coworld

Territory ships as **one Docker image** — the game host and every policy, switched by env — plus a
generated manifest.

```
compose.yaml                      service `territory`, image `territory-coworld:latest`
Dockerfile                        node:20-slim + the pre-built dist/ and dist-server/, plus two
                                  entrypoint shims: /bin/territory and /bin/territory-player
coworld_manifest_template.json    GENERATED by `pnpm emit-manifest`; never hand-edited
tools/build_replay_viewer.sh      the `coworld build` replay-viewer hook (mode 100755)
tools/ci/policies.json            the policy set coworld-release.yml uploads
```

## Build

```bash
pnpm install --frozen-lockfile
pnpm build                        # dist/ (the web bundle) + dist-server/ (self-contained bundles)
pnpm emit-manifest > coworld_manifest_template.json
docker compose -f compose.yaml build
```

The image COPIES the pre-built bundles, so they must be built in the same run that builds the image
— a stale bundle silently produces wrong gameplay. `ci.yml`'s `docker-smoke` job does exactly that.

## The two entrypoints

| binary | what it is | selected by |
|---|---|---|
| `/bin/territory` | the game host (`dist-server/coworld/game-cli.js`) | manifest `game.runnable.run` |
| `/bin/territory-player` | every policy (`dist-server/game/player.js`) | `PLAYER_PROMPT` (+ `USE_BEDROCK=true`) for the LLM policy, `PLAYER_JEV=1` for Jev, `PLAYER_SCRIPTED=homesteader\|raider` for a baseline, neither ⇒ `homesteader` |

`USE_BEDROCK: "true"` is **not optional** on an LLM policy: the platform gates the player pod's
Bedrock sidecar on it, and without it a `PLAYER_PROMPT` seat silently plays scripted — invisibly to
`results.fallbacks`.

Jev also runs in the player container. Use `PLAYER_JEV=1` and `USE_BEDROCK=true`
for the hosted TypeSafe sidecar, or `PLAYER_JEV=1` with `TYPESAFE_API_KEY` for
local inference. Keep these credentials on the player, never the game.

## The replay viewer

The manifest declares `"replay_viewer": {"bundle": "build/static-replay-viewer"}`. There is **no
wasm** in this lineage: the bundle is a **vite build of the same TypeScript sim the host runs**,
which satisfies the "the viewer re-derives every frame from the recorded events in the browser" pin
by compiling the engine to JS instead.

```bash
tools/build_replay_viewer.sh "$PWD/build/static-replay-viewer"
```

`coworld build` hard-requires `os.X_OK` on that hook, so it is committed **mode 100755** and CI
asserts the bit. Certification must report
`Replay liveness: skipped (static replay bundle declared` — a `/client/replay` pod viewer is a bug.

## Local episode

`tools/ci/docker_smoke.sh` is the containerised twin of a hand-run episode: one game container plus
**nine** player containers on a per-run docker network, driven by the certification fixture out of
the manifest, asserting the game exits 0, **every player** exits 0, `results.json` validates with
nine scores, and the replay parses as strict JSON.

```bash
./tools/ci/docker_smoke.sh territory-coworld:ci
```

It runs with **no** `ANTHROPIC_API_KEY` on purpose, which is also the proof that the keyless path
plays scripted and still completes.

## Release

Dispatch `.github/workflows/coworld-release.yml`. Its step order is load-bearing:

1. `coworld build`
2. `coworld certify` (fails unless the static-replay-bundle line appears)
3. `coworld upload-policy` for every entry in `tools/ci/policies.json` — **before** step 4
4. `coworld upload-coworld --wait-hosted-smoke`
5. `coworld secret put territory anthropic_api_key …` — **after** step 4, because the secret
   namespace does not exist until the Coworld does

Champion #2 (`territory-condottiere`) carries `"player": "ply_bac48eb1-…"`, so that one upload is
wrapped in `softmax player use` / `unset`: a version uploaded as `daveey` cannot later be submitted
as `daveey-1`.
